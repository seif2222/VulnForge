# EXPECTED — vulnerable-npm

Ground truth for the `vulnerable-npm` fixture. Three direct dependencies, no transitive
ones, each with recorded osv.dev advisories. A scan must produce exactly **10 findings**:
one per distinct CVE id.

## How this was verified

Every package was queried against the OSV.dev API
(`POST https://api.osv.dev/v1/query`, `ecosystem: "npm"`) on **2026-10-08**; the recorded
responses are committed under `fixtures/osv/` (`npm__lodash@4.17.20.json`,
`npm__minimist@1.2.5.json`, `npm__qs@5.2.0.json`). Canonical ids, affected ranges, fixed
versions and ratings below are read from those records, not written from memory. The
`package-lock.json` was generated by `npm install --package-lock-only` (lockfile v3, real
registry integrity hashes). Nothing here is unverified.

## Files

- `package.json` — three direct dependencies, pinned to exact versions.
- `package-lock.json` — lockfile v3, generated by `npm install --package-lock-only`.
  No `node_modules` is installed and none is needed.

## Notes for the engine

- A finding is one row per (CVE id, package@version). Ten OSV records become ten rows
  because each record names exactly one distinct CVE after the twin-advisory merge
  through the GHSA ids.
- The `Other ids` column must appear in each finding's `aliases`, never in `id`, and a
  finding's id must never appear in another finding's aliases.
